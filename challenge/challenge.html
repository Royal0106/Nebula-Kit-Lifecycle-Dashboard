Kit Lifecycle Dashboard

Every Nebula order goes through a physical and lab pipeline. Ops needs to know where kits are, how long each step takes, and which kits need someone to follow up. Build a small web app that answers those questions.

This is a simplified, made-up version of our fulfillment pipeline, built only for this exercise. The data is synthetic, and nothing you build will be used in production.

Please don't spend more than 2 hours. We don't expect you to finish everything. Submit what you have and tell us in the README what you'd do next.

Use any tech stack you like, and deploy it however you want.

The pipeline

We ship a kit. The customer collects a saliva sample and mails it back. The lab runs QC and sequencing, and then the customer's report is ready.

  1. kit_shipped
  2. kit_delivered
  3. sample_mailed
  4. sample_received
  5. qc_passed / qc_failed
  6. sequencing_complete
  7. report_ready

Sometimes a kit is replaced, for example after a failed QC or a lost package. A kit_replaced event is logged, and a new kit with a new kit_id starts again from kit_shipped.

What to build

A web app that someone on the ops team can open and use right away. At minimum, it should let them:

  • See how the pipeline is doing overall: volume, where kits are right now, and how many have finished.
  • Understand how long each stage takes, and how that differs by product.
  • Find kits that are stuck and need follow-up.
  • Drill into a single order and see what happened to it.
  • Narrow things down, for example by date, product or country.
  • Load a different pair of CSVs with the same columns. We'll test your app with our own data.

Beyond that, build whatever you think would be most useful. Choose where to spend your time.

What to submit

  1. A deployed URL we can open directly, with no login, no local setup and no build step on our end. Any free host is fine.
  2. A link to the source repo.
  3. A README (see below).

About the README

Write the README yourself, without AI. We want your own words, and short is fine. Cover:

  • The decisions and assumptions you made about the data, and why.
  • What you'd do next with more time.
  • How you used AI during the build, including at least one place where it got something wrong.

Questions? Reply to the email that sent you this challenge. If something is unclear, making a reasonable assumption and writing it down is a perfectly good answer.
